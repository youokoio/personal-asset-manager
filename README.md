# Personal Asset Manager v0.6.1-alpha1

## 概要
- iPhone Safari / ホーム画面追加PWA向けの個人用資産管理アプリ
- 資産データは端末内の IndexedDB に保存
- オフライン起動用 Service Worker
- JSONバックアップ／復元、AES-256-GCM暗号化バックアップ
- 口座、FX建玉、残高スナップショット、保有資産の登録・編集
- 時系列履歴と変更監査
- 口座間振替、単独入金、単独出金、手数料のみの記録
- 口座間振替は元口座・先口座を1件の履歴で管理し、両口座への増減を自動計算
- FX建玉の約定日・固定約定レート・記録時参考レートを分離
- FX建玉は未決済／全数量決済の二択。決済数量・残数量は自動計算
- 履歴一括入力：口座ごとの時系列履歴を複数行まとめて登録・編集（v0.5.0-alpha2）
- **v0.6.0-alpha1で追加・強化**：保存の安全化（失敗時ロールバック）、IDと建玉固定情報の保護、決済の訂正、入出金の論理削除、JSONインポート検証と復元前の控え、総資産・総負債・純資産の表示、FX口座別サマリー、欠損を補間しない推移グラフ

**個人の資産データJSONや暗号化バックアップをGitHubへアップロードしないでください。** GitHub Pagesの公開領域にはアプリのソースコードだけを置きます。

## v0.5.0-alpha1/alpha2 → v0.6.0-alpha1 の更新手順（詳細は `GITHUB_DEPLOY_v0_6.md`）
1. 「データ管理」から**暗号化バックアップ**を作成し、端末外に保存します。
2. 上記8ファイル（`history-core.js`・`store-core.js`・`finance-core.js` を含む）をGitHubへアップロードし、同名ファイルを置き換えます。
3. iPhoneでアプリ（ホーム画面のアイコン）を**完全に閉じて**開き直します。画面の「バージョン」が `0.6.0-alpha1` でなければ、もう一度閉じて開き直してください（Service Workerの仕様で、1〜2回の開き直しが必要です）。
4. 口座・建玉・履歴が残っていることを確認します。端末内のIndexedDBデータは消去されません。初回起動時にデータ形式がschemaVersion 5へ移行され、移行前の状態は端末内に控えとして保持されます。

## 履歴一括入力の使い方
1. 「履歴一括入力」タブを開き、口座を選びます。口座の種別から入力項目セット（銀行／FX／証券／iDeCo・企業型DC／暗号資産）が自動で選ばれます。違う場合は手動で変更できます。
2. 「＋ 行を追加」で行を増やし、対象日と数値を入力します。「複製」で前の行を元に素早く入力できます。マイナスの値は「±」ボタンで切り替えます。
3. 既存の履歴を修正する場合は「既存の履歴を読み込む（編集）」で読み込み、値を直します。不要な行は「削除」（論理削除）を選びます。
4. 「確認画面へ」で内容を確認します。エラーがあると保存できません。新規／修正（変更前→変更後）／削除が一覧されます。
5. 「この内容で保存」で確定します。複数行は1回で保存され、途中で失敗しても一部だけ保存されることはありません。

- **対象日**（その値だった実際の日付）と**登録日時**（保存した日時）は別々に記録されます。
- 同じ日に複数行を登録できます（確認画面で注意が表示されます）。
- 入力途中の内容は端末内に自動で下書き保存され、アプリを閉じても復元されます（JSONバックアップには含まれません）。
- 計算できる項目は自動で補完されます（例：銀行の終了残高＝開始残高＋入金−出金＋調整、証券・DCの評価額＝有効元本＋含み損益(＋現金)、暗号資産の評価額＝数量×価格）。補完した項目は「自動計算」と記録されます。入力済みの値が計算と合わない場合は警告のみで、値は書き換えません。
- 修正の前後は各記録の「修正履歴」に、一括操作の概要は「操作履歴」に残ります。

## v0.6.1：正規化JSONの取り込み
`dataType: personal_asset_management` のJSON（一次資料を照合しながら作る正規化形式）を、「データ管理」から取り込めます。**既存データは上書き・削除せず追加のみ**で、同じJSONを再取り込みしても重複登録されません。仕様・項目の対応・重複防止ルールは `IMPORT_CANONICAL_v1.md` を参照してください。
- 個人資産情報を含むJSONは**GitHubに上げないでください**（`.gitignore` に主なファイル名のパターンを入れています）。アプリのソースコードだけを反映してください。
- JSONに楽天証券・iDeCo・企業型DC・暗号資産のデータが入っていない場合、それらは画面にも表示されません（アプリは推測して作りません）。

## v0.6の主な変更点
- **保存の安全化**：変更は複製に対して行い、検証とIndexedDB保存が成功した後にだけ画面のデータへ反映します。失敗時は変更前の状態を保ち、入力ダイアログも閉じません。
- **ID・固定情報の保護**：口座ID・建玉ID・保有資産IDは編集できません。建玉の約定日・約定数量・約定レートは登録後に変更できません。誤登録は削除して登録し直します（削除前の内容は操作履歴に残ります）。参照されている口座は削除できません。
- **決済の訂正**：決済済みの建玉を未決済に戻すには、通常編集ではなく「決済の訂正」を使います（理由必須。訂正前後・日時を記録）。
- **入出金・手数料の削除は論理削除**：記録は残り、一覧・集計から除外されます。
- **JSONインポート検証**：壊れたJSON、必須配列の欠落、将来バージョン、ID重複、日付・数値・参照の不整合を検出した場合は、部分的に読み込まずに問題箇所を表示します。取り込み・復元・全データ削除の直前の状態は、端末内に1世代控えとして保存され、「データ管理」から書き出せます。
- **概要画面**：総資産・総負債・純資産（評価データのない口座は0円ではなく「データなし」）、FX口座別の建玉数・純資産・為替差益・累計スワップ・最終更新日、最終保存日時。
- **推移タブ**：記録のある点だけを表示し、記録のない期間は補間せず「データなし」として表示します。
- **一括入力**：同じ内容の履歴の重複登録を防止、過去日付の登録・修正時に後続データへの影響を通知、数値の桁区切り、保存ボタンの連打対策。

## v0.4からの更新
1. v0.4で保存したIndexedDBのデータを引き継ぎます。
2. アプリを更新する前に、必ず「データ管理」から暗号化バックアップを作成してください。
3. v0.5のファイルでGitHub Pages上の同名ファイルを置き換えます。
4. iPhone Safariでサイトを再読み込みします。古い画面が残る場合はアプリの「手動で更新を確認」を実行し、画面を閉じて再度開いてください。
5. 起動後、口座・建玉・履歴が残っていることを確認します。

## 資金移動の登録
- 口座間振替：振替元・振替先を選ぶと、1件の記録から両口座の増減を計算します。
- 単独入金：入金先口座だけを指定します。
- 単独出金：出金元口座だけを指定します。
- 手数料のみ：売買手数料などを独立して登録できます。
- 手数料の扱いは「別途差し引く」「入出金額から差し引く」を選択できます。
- 入出金履歴と手数料履歴は変更履歴にも記録されます。

資金移動差額は登録した資金移動履歴の通貨別合計です。銀行やFX会社の最新残高スナップショットを自動で書き換えるものではありません。残高スナップショットとの自動照合・差額調整は後続段階で実装します。

## データ保護
- アプリの通常利用時に外部API・CDN・解析サービスへ資産データを送信しません。
- IndexedDB内のデータ自体は暗号化されません。暗号化されるのはエクスポートしたバックアップです。
- iOSによるサイトデータ削除・ストレージ整理に備え、定期的に暗号化バックアップを端末外の安全な場所へ保存してください。
- 暗号化バックアップのパスワードを忘れると復元できません。

## 現段階の未実装・制限
次の機能は後続段階で追加します（今回は拡張しやすい保存構造のみ用意）。
- FX口座スナップショット登録時の建玉再構成プレビュー・スワップ按分の画面（按分の計算関数は実装・単体テスト済み）
- スワップ単価の変更履歴（保存用の配列のみ予約）
- 銀行残高と入出金・振替履歴の差異表示（残高の基本式は一括入力の自動補完で使用）
- 証券・NISA・iDeCo・企業型DCの売却記録（売却金額・売却元本・確定損益・手数料）
- 暗号資産の購入・売却記録。取得単価の計算方式（総平均法・移動平均法・FIFO等）は税務上の確認が必要なため決定していません
- 住宅ローン（借入条件・金利履歴・返済・繰上返済・返済シミュレーション）。口座種別「住宅ローン／ローン」で残高を負債として集計する機能のみ
- 税金・ロスカット等の詳細計算

本版を更新する際は、必ずバックアップを作成し、`TEST_CHECKLIST_v0_6.md` を確認してから実データで運用してください。
